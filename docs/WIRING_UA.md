# Підключення і перша прошивка

*[English](WIRING.md)*

Як з'єднати програматор ESP32-C3 SuperMini з WT32-ETH01, прошити її вперше, а потім підключити WT32 без програматора (живлення, екран, кнопка). Схеми генерує [`wiring/gen_wiring.py`](wiring/gen_wiring.py).

> Розділ 1 (програматор → WT32) і перша прошивка (розділ 2) перевірені на залізі. Розділ 4 (екран, кнопка, USB-C у корпусі) — ще ні: порядок пінів узято з даташиту WT32-ETH01 v1.4 і [egnor/wt32-eth01](https://github.com/egnor/wt32-eth01). Назви пінів надруковані на обох платах: якщо назва відрізняється від малюнка, орієнтуйтеся на надруковану.

## 1. Програматор → WT32

![C3 SuperMini до WT32-ETH01](wiring/programmer.svg)

| C3 SuperMini | WT32-ETH01 | Навіщо |
|---|---|---|
| GPIO4 (UART1 TX) | IO3 / RXD0 | дані до WT32 |
| GPIO5 (UART1 RX) | IO1 / TXD0 | дані й лог від WT32 |
| GPIO6 | EN (будь-який з двох) | скидання; відкритий стік: C3 лише притягує до землі або відпускає |
| GPIO7 | IO0 | режим завантаження; відкритий стік, відпускається після старту (IO0 — вхід тактування Ethernet) |
| 5V | 5V | лише для прошивки й логу (див. примітку про живлення нижче) |
| GND | GND (будь-який) | обов'язково |

- **Ніколи не з'єднуйте 3V3 з 3V3.** C3 ніколи не подає на IO0 «1», прошивка лише притягує його до землі.
- **Лише одне джерело 5 V.** Поки червоний дріт 5V під'єднано, не живіть WT32 ні від чого іншого (наприклад, від її USB-C у корпусі). Щоб лишити програматор на WT32 з власним живленням, від'єднайте тільки дріт 5V; GND лишається.
- **Живлення: 5V програматора вистачає для прошивки й логу, але не для роботи.** Від виводу 5V C3, коли C3 у USB-порту ПК, WT32 (з будь-якою версією прошивки) по колу перезапускається від просідання живлення приблизно через 2,4 с після старту — саме коли Wi-Fi-станція запускається при піднятому Ethernet: у лозі `E BOD: Brownout detector was triggered`, далі скидання. Щоб прошивка працювала з Wi-Fi і Ethernet, дайте WT32 власне живлення 5 В (бажано від 1 А), від'єднайте червоний дріт 5V і лишіть до C3 тільки GND і чотири сигнальні дроти.

## 2. Перша прошивка

1. Прошити C3 і підключити його до Wi-Fi: [README програматора](../tools/c3-programmer/README_UA.md), кроки 1–2. Його сторінка — `http://c3prog.local`.
2. З'єднати C3 з WT32, як вище, і ввімкнути C3 в USB. На WT32 засвітиться світлодіод живлення.
3. Перевірити зв'язок:
   ```bash
   esptool.py --chip esp32 -p rfc2217://c3prog.local:4000 flash_id
   ```
   Має показати чип (ESP32-D0WD…) і розмір флешу (4 МБ). Якщо не з'єднується — спершу поміняйте місцями дроти TX/RX. Якщо не спрацьовує автоскидання — натисніть «Режим прошивки» на сторінці C3 і додайте `--before no_reset`.
4. Уперше стерти флеш (на ньому заводська AT-прошивка), потім записати повний образ:
   ```bash
   esptool.py --chip esp32 -p rfc2217://c3prog.local:4000 erase_flash
   esptool.py --chip esp32 -p rfc2217://c3prog.local:4000 write_flash 0x0 wt32/firmware/wt32-bridge.bin
   ```
5. Дивитися лог (`--rts 0 --dtr 0` обов'язково, інакше WT32 лишається в скиданні):
   ```bash
   python -m serial.tools.miniterm --rts 0 --dtr 0 rfc2217://c3prog.local:4000 115200
   ```
   Після повідомлень старту кожні 10 с з'являється рядок-підсумок; з екраном у лозі також буде `SSD1306 at 0x3C` (або `0x3D`).
6. Телефоном підключитися до точки **`WT32-Setup-XXXX`** → http://192.168.4.1 (пароль сторінки `12345678`) і вибрати режим. Далі — чекліст у [`wt32/README_UA.md`](../wt32/README_UA.md).

Якщо імена `.local` не працюють (часто у Windows без Bonjour), беріть IP C3 з його сторінки стану або з роутера.

### Якщо щось не так

- **WT32 перезапускається кожні кілька секунд, у лозі `Brownout detector was triggered`:** вона живиться від 5V програматора. Дайте їй власне живлення 5 В (див. примітку про живлення в розділі 1).
- **esptool або miniterm втрачає зʼєднання під час скидання, після цього WT32 лишається в скиданні, а C3 не приймає нових зʼєднань:** ПК, на якому запущено esptool/miniterm, має ще й дротовий інтерфейс за WT32 (наприклад, коли ПК сам є пристроєм для перевірки), і ОС пускає зʼєднання RFC2217 через WT32 (у Windows Ethernet часто має метрику 5 проти 35 у Wi-Fi). Скидання через RTS тоді обриває те саме зʼєднання, яким воно надіслане. C3 тоді тримає EN у нулі, тож WT32 лишається в скиданні, і не приймає нових клієнтів до перезапуску (BOOT 5–10 с або перепідключення USB); C3 0.4.2 натомість відпускає EN приблизно через 3 с (перевірено: WT32 повертається за 6–10 с), але приймає нового клієнта лише через 31–34 с. Щоб цього уникнути, зробіть так, щоб ПК ходив до C3 через інший інтерфейс: привʼяжіть клієнт до нього або додайте маршрут до адреси C3.

## 3. Після прошивки: з програматором чи без

- **Лишити під'єднаним** — щоб бачити лог і перепрошивати по Wi-Fi. C3 відпускає EN і IO0, тож WT32 працює як звичайно.
- **Зняти:** від'єднати шість дротів і живити WT32 окремо (розділ 4). Наступні оновлення — через сторінку WT32: розділ «Прошивка», файл `wt32/firmware/wt32-bridge-ota.bin`, з відкатом, якщо нова прошивка не стартує. Кабель знову знадобиться, лише якщо WT32 зовсім не завантажується.

## 4. WT32 окремо (у корпусі)

![WT32-ETH01 з живленням, екраном і кнопкою](wiring/standalone.svg)

| Звідки | WT32-ETH01 | Примітка |
|---|---|---|
| Перехідник USB-C, VBUS / 5V | 5V | перехідник USB-C «лише живлення» |
| Перехідник USB-C, GND | GND | |
| OLED VCC | **3V3** | не 5V: на деяких модулях підтяжки I2C — до їхнього живлення |
| OLED GND | GND | |
| OLED SDA | IO32 (надруковано CFG) | |
| OLED SCL | IO33 (надруковано 485_EN) | |
| Кнопка, одна ніжка | IO4 | внутрішня підтяжка, резистор не потрібен |
| Кнопка, друга ніжка | GND | |

- Порядок пінів OLED у різних модулів різний (GND-VCC-SCL-SDA або VCC-GND-SCL-SDA): з'єднуйте за назвами, надрукованими на вашому.
- Екран і кнопка необов'язкові. Що робить кнопка (коротко, 5 с, 10 с) — у [`wt32/README_UA.md`](../wt32/README_UA.md).
- У корпусі дроти паяються до пінів: роз'єми Dupont не поміщаються по висоті (див. [`hardware/case/README_UA.md`](../hardware/case/README_UA.md)).
