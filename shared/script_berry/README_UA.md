# Скрипти на Berry

*[English](README.md)*

Компонент запускає **один** скрипт користувача мовою [Berry](https://github.com/berry-lang/berry) — легкою мовою для мікроконтролерів (її використовує Tasmota). Скрипт пишеться й запускається на сторінці пристрою (розділ «Скрипт (Berry)»).

> Статус: зібрано в прошивку WT32; мовну частину (прелюдія, таймери, ліміти, помилки) перевірено на ПК справжнім Berry з цією конфігурацією, сторінку — у браузері. На залізі **не перевірено**.

## API скрипта

| Виклик | Що робить |
|---|---|
| `print(...)` | рядок у консоль сторінки (і в UART-лог) |
| `output(ключ, значення)` | результат у таблиці «Результати» (до 16 ключів; далі — і на екрані) |
| `output(ключ)` | прибирає результат |
| `every(мс, fn)` → id | викликати `fn` кожні `мс` |
| `after(мс, fn)` → id | викликати `fn` один раз через `мс` |
| `cancel(id)` | скасувати таймер |
| `status()` → map | стан пристрою — ті самі поля, що на сторінці (`mode`, `eth`, `devIp`, `devMac`, …) |
| `millis()` | мс від старту |
| `heap()` | вільна памʼять пристрою, байти |

Стандартні модулі: `string`, `json`, `math`, `time`, `global`, `gc`, `introspect`, `strict` (через `import`). Файлової системи немає.

```berry
def show()
  var s = status()
  output("IP пристрою", s["devIp"] != "" ? s["devIp"] : "—")
end
show()
every(5000, show)
```

## Обмеження й захист

- **Памʼять**: бюджет скрипта — 40 КБ (`menuconfig` → `WT32_SCRIPT_MEM_KB`). Понад нього — помилка `memory_error`, скрипт зупиняється, памʼять повністю звільняється; Wi-Fi, Ethernet і сторінка не страждають.
- **Час**: одне виконання коду скрипта (верхній рівень або один таймер) — до 2 с. Нескінченний цикл зупиняється з `timeout_error`.
- **Помилки**: будь-яка необроблена помилка зупиняє скрипт; на сторінці — тип, текст і рядок (`script:12: …`).
- **Аварії**: якщо пристрій перезапустився через збій, поки працював код скрипта, автозапуск вимикається (сторінка про це скаже).
- **Розмір**: до 32 КБ тексту; зберігається в розділі `storage` (з контрольною сумою), компілюється прямо з флешу.
- Скрипт працює в окремій задачі на другому ядрі з низьким пріоритетом.

## Як влаштовано

| Файл | Що робить |
|---|---|
| `berry/` | Berry (git-субмодуль, закріплений на коміті) |
| `port/berry_conf.h` | конфігурація: 32-біт цілі, float, без ФС/ОС-модулів, лічильник інструкцій для ліміту часу, аллокатор з бюджетом |
| `port/be_port.c`, `be_modtab.c` | вивід у консоль, заглушки файлів, список модулів |
| `prelude.be` | таймери й `status()` на самому Berry |
| `script_runtime.c` | задача, ліміти, консоль, результати, захист від аварій |
| `script_store.c` | текст у розділі `storage` |
| `script_web.c`, `script.js` | маршрути `/api/script*` і розділ сторінки |

Таблиці констант Berry генеруються під час збірки його ж інструментом `tools/coc` (Python з оточення ESP-IDF).

**Після клонування репозиторію:** `git submodule update --init` (або `git clone --recursive`). `wt32/build_firmware.sh` робить це сам.

## Тест на ПК

```bash
shared/script_berry/test/run_host_test.sh
```
Збирає Berry з `port/berry_conf.h` і перевіряє: приклад зі сторінки WT32, таймери `every/after/cancel`, зупинку нескінченного циклу, бюджет памʼяті (з повним звільненням), синтаксичну помилку з номером рядка.
