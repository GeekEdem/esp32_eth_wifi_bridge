# WT32-ETH01: Wi-Fi для одного Ethernet-пристрою

*[English](README.md)*

Основна прошивка. WT32 під'єднується кабелем до **одного** пристрою (будь-якого) і дає йому Wi-Fi (або, в режимі «Точка доступу», роздає по Wi-Fi мережу роутера з кабелю). Прошивка нічого не знає про пристрій і не змінює його дані — лише пересилає кадри.

> Статус: зібрано (ESP-IDF 6.1), логіку пересилання, службового порту і скриптів перевірено тестами на ПК, сторінку — у браузері проти імітації API. На залізі **не перевірено**.

## Три режими (вибір на сторінці, застосовується після перезапуску)

### Клієнт (за замовчуванням)
WT32 підключається до наявного Wi-Fi. Пристрій отримує IP від роутера цієї мережі й доступний, ніби під'єднаний до роутера кабелем.

- Wi-Fi-клієнт може мати лише одну MAC, тож кадри пристрою виходять з **MAC станції WT32**, а MAC у ARP і DHCP (chaddr, опція 61) переписуються. Роутер бачить одного клієнта — під MAC станції WT32 (друкується в лозі при старті). Закріпіть IP на роутері за цією MAC.
- Власної IP WT32 не має: він використовує IP пристрою і забирає собі лише нові TCP-з'єднання на порт **28480** та з'єднання, які відкрив сам. Broadcast, multicast і ARP отримують обидва; усе інше (сервіси пристрою на будь-яких портах, його веб-сторінка на 80, ping) — пристрій. Маска, шлюз і DNS — з DHCP-відповіді роутера пристрою.
- Сторінка: **`http://<IP пристрою>:28480`**. Поки мережу не налаштовано, вона недоступна понад 60 с або IP пристрою ще невідома, сторінка є ще й на точці **`WT32-Setup-XXXX`** → http://192.168.4.1 (відкрита, без пароля Wi-Fi).
- IPv6 не пересилається (у пакетах сусідів MAC не переписується).

### Роутер
WT32 роздає власний Wi-Fi (WPA2/WPA3). Точка доступу й Ethernet — одна мережа з DHCP-сервером на WT32: пристрій на кабелі й телефони отримують адреси й бачать одне одного. Інтернету немає (NAT не потрібен: немає куди виходити).

- WT32 — `192.168.77.1` (змінюється), пул DHCP — `.100–.200`; сторінка — `http://192.168.77.1` або `http://wt32.local`.
- IP пристрою видно на сторінці (WT32 запам'ятовує його MAC з першого кадру й шукає видану адресу).
- DHCP-сервер власний (`dhcp_core.c`): оренда 2 год, до 32 клієнтів; клієнт за своєю MAC отримує ту саму адресу. У розділі «Адреси в мережі (DHCP)» сторінки — список клієнтів (пристрій на кабелі позначено) і **закріплення IP за MAC** (кнопкою в рядку або вручну; адреса — будь-яка в підмережі, крім адреси WT32). Оренди й закріплення зберігаються в NVS і переживають перезапуск; закріплення — одразу, оренди — раз на 30 с.
- Шлюзом DHCP видає адресу WT32, DNS не видає (інтернету немає).

### Точка доступу
Кабель WT32 — у роутер (або світч мережі з DHCP), а WT32 роздає цю мережу по Wi-Fi. Точка доступу й Ethernet — один міст: адреси (DHCP), інтернет, пошук пристроїв — усе від роутера, WT32 нічого не змінює.

- WT32 — ще один клієнт DHCP цієї мережі (ім'я `wt32`); сторінка — `http://<адреса WT32>` (є в списку клієнтів роутера і на UART) або `http://wt32.local`.
- **Немає DHCP на кабелі 30 с** (кабель витягнули, роутер перезавантажується) → WT32 бере запасну адресу (поле «Запасна адреса WT32», за замовчуванням `192.168.77.1`) і сам видає адреси `.100–.200` **лише клієнтам своєї точки доступу**, з орендою 2 хв — щоб сторінка лишалась доступною. У цей час кожні 30 с і при підключенні кабелю WT32 шле пробний DHCP-запит; щойно роутер відповідає — повертається до його DHCP, а клієнти за 1–2 хв переходять на адреси роутера.
- Назва, пароль і канал Wi-Fi — спільні з режимом «Роутер».

## Сторінка

Під паролем: за замовчуванням **`12345678`**, змінюється в розділі «Пароль сторінки» (8–63 символи); поки стоїть стандартний — нагадування. Сесія — 30 хв бездіяльності; 5 невдалих спроб поспіль блокують вхід на 30 с.

- **Стан**: режим, Wi-Fi, Ethernet, MAC/IP пристрою, адреса сторінки; у режимі клієнта — лічильники трафіку з поясненнями.
- **Режим**: перемикач «Клієнт» / «Роутер» / «Точка доступу»; для клієнта — вибір Wi-Fi і пароль; для роутера й точки доступу — назва, пароль (8–63), канал, адреса WT32 (для точки доступу — запасна).
- «Забути пристрій (після заміни)» — після заміни пристрою на кабелі (клієнт). «Забути Wi-Fi клієнта» — повернення в точку налаштування.

**Забули пароль сторінки або мережі WT32** → утримати кнопку 10 с (див. нижче). Без кнопки — стерти флеш і прошити заново (зітре всі налаштування):
```bash
esptool.py --chip esp32 -p rfc2217://c3prog.local:4000 erase_flash
esptool.py --chip esp32 -p rfc2217://c3prog.local:4000 write_flash 0x0 firmware/wt32-bridge.bin
```

## Екран і кнопка (необовʼязково)

OLED 0,96″ 128×64 I2C (SSD1306) і одна кнопка. Без них усе працює; без екрана кнопка теж працює.

| Що | Пін WT32 |
|---|---|
| OLED VCC | **3V3** (не 5 V: підтяжки I2C на модулі — до його живлення) |
| OLED GND | GND |
| OLED SDA | IO32 (на платі — CFG) |
| OLED SCL | IO33 (на платі — 485_EN) |
| Кнопка | між **IO4** і GND (внутрішня підтяжка, резистор не потрібен) |

- Екран знаходиться сам за адресою 0x3C або 0x3D (у лозі: `SSD1306 at 0x3C`). Гасне через 60 с без натискань (OLED вигорає від постійної картинки).
- Сторінки: **Мережа** (режим, Wi-Fi, адреса сторінки WT32), **Пристрій** (Ethernet, MAC, IP; у точці доступу — **Кабель**: DHCP роутера, шлюз), **Трафік** (клієнт), **Скрипт** (перші 5 `output()` скрипта, якщо є), **Система** (версія, памʼять, час роботи).
- **Кнопка** (дія — коли відпустити; поки тримаєте, екран показує, що станеться):
  - коротко — увімкнути екран / наступна сторінка;
  - **5 с** — разовий запуск для налаштування: WT32 перезапускається в режимі «Клієнт» з точкою `WT32-Setup-XXXX` (http://192.168.4.1). Збережений режим не змінюється: після наступного перезапуску WT32 повертається до нього, якщо на сторінці не збережено інше;
  - **10 с** — скидання: стирає всі налаштування (режим, мережі, пароль сторінки → `12345678`, оренди DHCP, автозапуск скрипта); текст скрипта лишається;
  - 1–5 с — нічого (скасування). Кнопка, затиснута під час увімкнення, ігнорується, доки її не відпустять.

## Скрипти (Berry)

Розділ «Скрипт (Berry)» на сторінці: редактор, «Зберегти й запустити», «Зупинити», «Запускати при старті», таблиця «Результати» і консоль. Скрипт може читати стан пристрою (`status()`), виводити результати (`output()`), працювати за таймерами (`every`, `after`). Опис API й обмежень — [`../shared/script_berry/README_UA.md`](../shared/script_berry/README_UA.md).

- Бюджет памʼяті скрипта — 40 КБ, одне виконання коду — до 2 с; помилка зупиняє лише скрипт.
- Якщо пристрій перезапустився через збій під час роботи скрипта, автозапуск вимикається.
- Ціна у прошивці: ~102 КБ флешу, ~6,5 КБ постійної RAM; під час роботи — ще 10 КБ стеку задачі та бюджет скрипта.

## Оновлення прошивки через сторінку (OTA)

Розділ «Оновлення прошивки» на сторінці: файл **`firmware/wt32-bridge-ota.bin`** → «Оновити прошивку». Повний образ `wt32-bridge.bin` (для адреси `0x0`) сторінка відхилить — він лише для прошивки кабелем.

- Перед записом перевіряється, що образ для цього чипа і цієї прошивки; після запису — цілісність.
- Флеш має два слоти (`ota_0`/`ota_1`, по 1,875 МБ); нова прошивка пишеться в неактивний, старий лишається.
- Після перезапуску нова прошивка **на перевірці 60 с**: якщо за цей час вона впаде або перезапуститься, завантажувач повертає попередню. Сторінка покаже, яка версія реально працює.
- Сесії не переживають перезапуск — сторінка попросить увійти знову.
- Перший раз прошивку з цією розміткою треба записати кабелем (повний образ з `0x0`); налаштування (NVS) при цьому зберігаються.

## 1. Прошити WT32 через C3

Схеми підключення і перша прошивка крок за кроком: [`docs/WIRING_UA.md`](../docs/WIRING_UA.md).

Підключення C3 ↔ WT32 — див. [`../tools/c3-programmer/README_UA.md`](../tools/c3-programmer/README_UA.md).

```bash
esptool.py --chip esp32 -p rfc2217://c3prog.local:4000 write_flash 0x0 firmware/wt32-bridge.bin
```

Лог (кожні 10 с — підсумок режиму):
```bash
python -m serial.tools.miniterm --rts 0 --dtr 0 rfc2217://c3prog.local:4000 115200
```
`--rts 0 --dtr 0` обовʼязково: інакше RTS тримає WT32 у скиданні.

## 2. Перше налаштування

1. Телефоном до **`WT32-Setup-XXXX`** → відкриється сторінка (або http://192.168.4.1), пароль `12345678`.
2. Режим «Клієнт»: обрати домашню мережу, пароль → «Зберегти і перезапустити».
   Або «Роутер» / «Точка доступу»: назва, пароль, канал → «Зберегти і перезапустити».
3. Змінити пароль сторінки.

## 3. Чекліст перевірки з пристроєм

Будь-який мережевий пристрій у режимі **DHCP** (для перевірки — принтер). Патч-корд пристрій ↔ WT32. «Звична робота» — те, для чого пристрій у мережі (принтер — друк з ПК, камера — відео тощо).

**Підказки на сторінці «Трафік»** (клієнт):
- «Відкинуто: Wi-Fi не підключено» росте — WT32 не тримає Wi-Fi (дивись RSSI);
- «Кадри від другого пристрою» > 0 — на Ethernet більше одного пристрою (світч?) — підтримується лише один;
- «DHCP-перезаписи» = 0, а IP немає — пристрій не шле DHCP (статична IP з іншої підмережі?);
- «Помилки передачі» ростуть — відкрийте issue з логом UART.

## Структура

| Файл | Що робить |
|---|---|
| `main/main.c` | вибір режиму на старті, лог, дії кнопки (разовий запуск налаштування, скидання) |
| `main/settings.c` | режим і налаштування точки доступу WT32 в NVS |
| `main/eth.c` | EMAC + LAN8720 (WT32-ETH01) |
| `main/client_mode.c` | режим «Клієнт»: пересилання, інтерфейс керування на спільній IP |
| `main/l2rewrite.c` | перезапис MAC у кадрах, ARP, DHCP; перехоплення DHCP ACK |
| `main/mgmt_demux.c` | кому кадр з Wi-Fi: пристрою, WT32 чи обом |
| `main/own_mode.c` | режими «Роутер» і «Точка доступу»: AP + Ethernet у мості; DHCP-клієнт із запасною адресою |
| `main/dhcp_core.c` | логіка DHCP-сервера (без ESP-IDF): пул, оренди, закріплення, збереження; пробний DHCP-запит |
| `main/dhcp_server.c` | DHCP-сервер: UDP 67, збереження в NVS |
| `main/display.c` | екран SSD1306 (I2C) і кнопка: задача, що малює сторінки |
| `main/disp_ui.c`, `main/font6x10.c` | сторінки екрана (без ESP-IDF); шрифт 6×10 з кирилицею (misc-fixed, public domain; `tools/gen_font.py`) |
| `main/button.c` | кнопка (без ESP-IDF): антидребезг і тривалість натискання |
| `main/web.c`, `main/page.html` | сторінка; Wi-Fi, пароль, OTA і портал — `shared/wifi_setup`; скрипти — `shared/script_berry` |
